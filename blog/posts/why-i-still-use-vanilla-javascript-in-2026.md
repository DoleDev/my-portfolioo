Frameworks dominate modern web development. React, Vue, Svelte, and Next.js are excellent tools — I use them regularly. But I still write a surprising amount of pure vanilla JavaScript in 2026. Here's why.

## The Case for Simplicity

Not every project needs a framework. When you're building:

- A personal portfolio
- A landing page
- A documentation site
- A small interactive tool
- A Telegram Mini App frontend

…adding a full framework often creates more complexity than value.

Vanilla JavaScript has become extremely capable. Features that once required libraries are now native:

- Fetch API
- Intersection Observer
- CSS Custom Properties
- ES Modules
- Optional chaining and nullish coalescing
- Top-level await

## Performance Wins

A framework comes with a cost — usually 30–100 KB of JavaScript just to get started. On a mobile connection or low-powered device, that extra weight is noticeable.

With vanilla JS I can ship interactive pages that load in under a second and score 95+ on Lighthouse without fighting the framework.

## Longevity

A site built with plain HTML, CSS, and JavaScript in 2019 still works perfectly today. The same cannot always be said for projects locked to a specific major version of a framework.

When I revisit old projects, the vanilla ones require almost no maintenance. The framework-based ones often need dependency updates, breaking change fixes, and build tool migrations.

## When I Reach for a Framework

I still use frameworks when the project genuinely needs them:

- Complex state management across many components
- Large teams that benefit from strong conventions
- Applications with heavy client-side routing
- Projects that will grow significantly over time

The key is choosing the right tool for the job, not defaulting to the most popular one.

## Final Thoughts

Vanilla JavaScript is not outdated — it's foundational. Understanding it deeply makes you better at every framework. And for many real-world projects, it remains the fastest, lightest, and most future-proof option available.

Next time you start a project, ask yourself: "Do I actually need a framework for this?"

You might be surprised how often the answer is no.
